## 1. 프로젝트 개요 (한눈에 보기)

### 프로젝트 목적
- 브라우저에서 컵의 이동을 눈으로 따라가 공이 숨겨진 컵을 찾는 야바위 게임을 제공한다.
- 정답을 맞히면 점수를 얻고 다음 레벨로 진행한다. 오답을 고르면 게임이 끝난다.
- 레벨이 높아질수록 컵 수와 섞기 횟수가 늘고 이동이 빨라진다.
- 게임 종료 후 점수를 Neon PostgreSQL에 저장할 수 있고, 전체 플레이어의 TOP 5 랭킹을 확인할 수 있다.

### 핵심 화면과 규칙
- 공개 게임 경로는 `/` 하나다. 점수 API 경로는 `/api/scores`와 `/api/scores/top5`다.
- 로그인 없이 플레이한다. 점수 저장은 게임 종료 후 닉네임을 입력하고 저장 버튼을 눌러 직접 요청한다.
- 현재 게임 점수는 게임 중 계속 표시한다. 개인 최고 점수는 브라우저의 `localStorage`에 저장해 다음 방문에도 표시한다.
- 모든 컵 카드는 같은 불투명 흰색(`#FFFFFF`)과 같은 테두리·그림자를 사용한다. 카드 위치나 순서에 따라 외관을 바꾸지 않는다.
- 공은 시작 전 잠깐 보여 주고, 섞는 중과 선택 대기 중에는 숨긴다. 컵을 선택한 뒤에만 결과 확인을 위해 보여 준다.

### 기술 제약
- Next.js App Router와 Neon PostgreSQL을 사용한다. DB 연결은 서버에서만 수행하며 `DATABASE_URL`을 브라우저에 노출하지 않는다.
- 배포는 GitHub 저장소와 Vercel을 사용한다. 공개 경로 `/`는 DB 연결 없이 HTTP 200으로 렌더링되어야 한다.

## 2. 사용자와 사용 시나리오

### 대상 사용자
- 별도 회원가입 없이 PC 또는 모바일 브라우저에서 짧은 두뇌 게임을 즐기려는 사용자.
- 다른 플레이어의 점수와 자신의 점수를 비교하고 싶은 사용자.

### 사용 시나리오
1. 사용자는 `/`에서 게임 시작 버튼과 개인 최고 점수를 확인한다.
2. 게임을 시작하면 공의 위치가 1.5초간 공개된다.
3. 컵이 이동하는 동안 사용자는 이동을 관찰한다. 섞기가 끝나면 컵 하나를 선택한다.
4. 정답이면 현재 레벨 점수를 얻고 다음 레벨로 자동 진행한다. 오답이면 최종 점수와 기록 저장 입력란이 표시된다.
5. 사용자는 2~8자의 닉네임으로 점수를 저장하거나 저장하지 않고 다시 도전할 수 있다.
6. 사용자는 랭킹 버튼으로 전체 점수 중 상위 5개 기록을 확인한다.

## 3. 기능 명세

### 1. 게임 상태와 진행
게임 상태는 `IDLE`, `PREVIEW`, `MIXING`, `CHOOSING`, `REVEAL`, `ROUND_CLEAR`, `GAME_OVER` 중 하나다.

| 상태 | 동작 |
| --- | --- |
| `IDLE` | 게임 시작 가능. 점수 0, 레벨 1을 표시한다. |
| `PREVIEW` | 공이 들어 있는 컵을 들어 올려 공을 1,500ms 보여 준다. |
| `MIXING` | 컵이 정해진 순서로 자리를 바꾼다. 클릭·터치를 받지 않는다. |
| `CHOOSING` | 섞기가 모두 끝난 뒤 컵 선택을 받는다. |
| `REVEAL` | 선택한 컵을 열어 공 위치를 공개한다. 오답이면 정답 컵도 함께 공개한다. |
| `ROUND_CLEAR` | 정답 점수를 더하고 1,200ms 뒤 다음 레벨을 시작한다. |
| `GAME_OVER` | 오답 결과, 최종 점수, 닉네임 입력 및 저장 UI를 표시한다. |

- 상태 전환은 `IDLE → PREVIEW → MIXING → CHOOSING → REVEAL` 순서로 진행한다.
- `REVEAL`에서 정답이면 `ROUND_CLEAR`로, 오답이면 `GAME_OVER`로 이동한다.
- 컵은 고정된 슬롯에 그려 두고 색이나 인덱스로 정답을 나타내지 않는다. 각 컵 요소는 고유한 ID를 유지하며, 섞을 때 두 컵의 슬롯 위치를 교환하고 `transform: translateX(...)` 애니메이션으로 이동시킨다.
- 섞기 애니메이션은 한 번에 한 쌍씩 실행한다. 각 이동이 끝난 뒤 해당 레벨의 대기 시간만큼 기다리고 다음 교환을 시작한다. CSS `transitionend`를 기다리되 이벤트가 누락되면 이동 시간에 100ms를 더한 타이머로 다음 교환을 진행한다.
- 게임 중 연속 클릭으로 여러 컵을 선택하거나 애니메이션을 중단할 수 없다.

### 2. 레벨과 점수
| 레벨 | 컵 수 | 교환 횟수 | 1회 이동 시간 | 교환 사이 대기 시간 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 3 | 4 | 750ms | 250ms |
| 2 | 3 | 6 | 650ms | 200ms |
| 3 | 4 | 7 | 550ms | 150ms |
| 4 | 4 | 9 | 480ms | 120ms |
| 5 | 5 | 10 | 420ms | 100ms |
| 6 이상 | 5 | `10 + 2 × (레벨 - 5)` | `max(250, 420 - 25 × (레벨 - 5))`ms | `max(60, 100 - 5 × (레벨 - 5))`ms |

- 레벨마다 공이 들어 있는 컵과 교환할 컵 쌍을 무작위로 정한다. 같은 컵 쌍이 연속으로 선택되는 것은 허용한다.
- 레벨을 통과하면 해당 레벨 점수 `레벨 × 100 + 컵 수 × 50`점을 추가한다. 오답이면 해당 레벨 점수는 추가하지 않는다.
- 레벨 1의 통과 점수는 450점이다. 점수와 레벨은 정수다.
- 개인 최고 점수는 현재 게임 점수가 더 높아질 때 갱신하고 `localStorage` 키 `cup-shuffle-best-score`에 저장한다. 저장값이 없거나 유효한 0 이상의 정수가 아니면 0으로 처리한다.

### 3. 공 표시와 동일한 컵 외관
- 모든 컵 카드는 배경 `#FFFFFF`, 불투명도 `1`, 테두리 `2px solid #FBCFE8`, 모서리 둥글기 `16px`, 동일한 그림자를 사용한다. 컵 번호나 슬롯 위치에 따른 색상·패턴 변화를 금지한다.
- `PREVIEW`에서만 정답 컵을 위로 50px 들어 올리고 공을 표시한다.
- `MIXING`과 `CHOOSING`에서는 공 요소를 렌더링하지 않는다. 컵이 완전히 불투명하므로 공이 카드 뒤로 비치지 않아야 한다.
- `REVEAL`, `ROUND_CLEAR`, `GAME_OVER`에서는 결과 확인에 필요한 공을 표시한다. 오답이면 선택 컵과 정답 컵을 함께 연다.

### 4. 점수 저장과 TOP 5
- 게임 종료 시 닉네임 입력란과 `기록 저장` 버튼을 표시한다. 닉네임은 앞뒤 공백을 제거한 뒤 2~8자로 검사한다.
- 저장 요청은 `POST /api/scores`로 보낸다. 저장 성공 후 버튼 문구를 `저장 완료 ✓`로 바꾸고 버튼과 입력란을 비활성화한다. 같은 게임 화면에서 다시 제출할 수 없다.
- 저장은 선택 사항이며, 저장하지 않고 `다시 도전하기`를 선택할 수 있다. 저장하지 않은 점수는 온라인 랭킹에 포함하지 않는다.
- `🏆 랭킹 보기`는 `GET /api/scores/top5`를 호출해 점수 내림차순, 동점이면 생성 시각 오름차순으로 최대 5개를 표시한다. 결과가 없으면 `아직 등록된 점수가 없습니다.`를 표시한다.
- API 오류가 나면 사용자에게 재시도 가능한 안내를 표시하며, 입력한 닉네임과 게임 점수는 유지한다.

### 5. 기능 수용 기준
- **카드 외관 통일** — Given 컵 여러 개가 화면에 보일 때, When 각 컵의 스타일을 비교하면, Then 배경·테두리·불투명도·그림자가 모두 같고 배경은 `#FFFFFF`, 불투명도는 `1`이어야 한다.
- **게임 시작과 공 공개** — Given 게임이 대기 상태일 때, When 사용자가 `게임 시작`을 누르면, Then 레벨 1의 정답 컵과 공이 1,500ms 동안 공개된 뒤 섞기가 시작되어야 한다.
- **컵 이동과 선택 제한** — Given 컵을 섞는 중일 때, When 사용자가 컵을 눌러도, Then 선택이 처리되지 않아야 한다. 모든 교환이 끝난 뒤에만 컵 선택이 가능해야 한다.
- **정답 진행과 점수** — Given 레벨의 정답 컵이 정해져 있을 때, When 사용자가 정답 컵을 선택하면, Then 해당 레벨 점수만큼 점수가 증가하고 1,200ms 뒤 다음 레벨이 시작되어야 한다.
- **오답 종료** — Given 선택 가능한 상태일 때, When 사용자가 오답 컵을 선택하면, Then 추가 점수 없이 게임이 종료되고 선택 컵과 정답 컵 및 최종 점수가 표시되어야 한다.
- **최고 점수 유지** — Given 개인 최고 점수가 저장된 상태일 때, When 사용자가 페이지를 새로 열면, Then 저장된 최고 점수가 표시되어야 한다.
- **점수 저장** — Given 게임 종료 후 유효한 닉네임을 입력했을 때, When `기록 저장`을 누르고 서버 저장이 성공하면, Then 기록이 DB에 추가되고 버튼과 입력란이 비활성화되어야 한다.
- **랭킹 조회** — Given DB에 기록이 있을 때, When 사용자가 랭킹을 열면, Then 최대 5개 기록이 점수 내림차순·동점 시 오래된 기록 우선으로 표시되어야 한다.

## 4. 화면과 주소(URL) 구성

### 경로
- `/`: 게임, 개인 최고 점수, 게임 종료 UI, 랭킹 모달을 포함하는 단일 페이지.
- `/api/scores`: 점수 저장 API. 페이지 경로가 아니다.
- `/api/scores/top5`: TOP 5 조회 API. 페이지 경로가 아니다.

### 메인 페이지 레이아웃
- 전체 배경은 `#FCE7F3`에서 `#F3E8FF`, `#E0F2FE`로 이어지는 좌상단-우하단 그라데이션이다.
- 화면은 세로 방향으로 구성하고 좌우 여백은 12px, 화면이 640px 이상이면 16px로 한다. 가로 스크롤은 발생하지 않아야 한다.
- 제목 문구는 `도전! 컵 섞기 야바위 게임 🥤`이다. 640px 미만에서는 18px 굵게, 그 이상에서는 24px 굵게 표시한다.
- 점수 표시 문구는 `Score: {현재점수}`, `Best: {최고점수}`, `Lv.{레벨}`이다. 게임 대기 중에도 표시하며 `Score`는 0, `Lv`는 1이다.
- 랭킹 버튼 문구는 `🏆 랭킹 보기`다.
- 안내 문구는 상태별로 다음을 사용한다.
  - `IDLE`: `게임을 시작하고 공이 숨겨진 컵을 찾아보세요!`
  - `PREVIEW`: `공이 들어 있는 컵을 기억하세요!`
  - `MIXING`: `컵을 잘 따라가세요!`
  - `CHOOSING`: `공이 들어 있는 컵을 선택하세요.`
  - `ROUND_CLEAR`: `정답이에요! 다음 레벨로 이동합니다.`
  - `GAME_OVER`: `아쉽네요! 게임이 끝났어요.`
- 대기 상태의 시작 버튼 문구는 `게임 시작`, 종료 모달의 재시작 버튼 문구는 `다시 도전하기`다.

### 게임 보드와 컵
- 보드 최대 너비는 560px, 높이는 모바일 210px·화면 640px 이상에서 240px로 한다. 컵 전체가 보드 안에 들어오도록 중앙 정렬한다.
- 슬롯 너비는 `min(가용 보드 너비 / 컵 수, 최대 슬롯 너비)`로 계산한다. 컵 카드 너비는 슬롯 너비보다 8px 작게 하고, 최대 너비는 80px로 한다. 카드 높이는 80~110px 범위에서 너비에 비례해 계산한다.
- 좌표 계산은 보드의 실제 너비를 기준으로 한다. 컵의 전체 슬롯 너비가 보드 너비를 넘으면 슬롯 너비와 컵 너비를 함께 줄인다. 320px 화면에서 5개 컵이 잘리거나 겹치지 않아야 한다.
- 모든 컵 카드의 스타일은 동일하다. 컵 클릭은 `CHOOSING` 상태에서만 가능하다.
- 컵은 고유 ID를 유지한 채 CSS transform으로 슬롯 사이를 이동한다. 이동 중 컵에 `pointer-events: none`을 적용한다.
- 공은 컵 아래에 위치한다. `PREVIEW`와 결과 공개 상태에만 보이고, `MIXING` 및 `CHOOSING` 상태에서는 DOM에 렌더링하지 않는다.

### 게임 종료와 랭킹 모달
- 종료 모달 제목은 `게임 오버`, 점수 문구는 `최종 점수: {점수}`다.
- 닉네임 입력 안내 문구는 `닉네임 (2~8자)`다. 유효하지 않을 때는 `닉네임은 공백을 제외하고 2~8자로 입력해 주세요.`를 표시한다.
- 저장 중 버튼 문구는 `저장 중...`, 성공 문구는 `저장 완료 ✓`, 실패 안내는 `점수를 저장하지 못했어요. 다시 시도해 주세요.`다.
- 저장 성공 후 닉네임 입력란과 저장 버튼은 비활성화한다. 재시작 버튼은 저장 여부와 관계없이 사용할 수 있다.
- 랭킹 모달은 순위, 닉네임, 점수, 날짜를 표시한다. 날짜는 브라우저 현지 시간대로 `YYYY.MM.DD` 형식으로 표시한다.
- 랭킹을 불러오는 중에는 `랭킹을 불러오는 중...`, 조회 실패 시 `랭킹을 불러오지 못했어요. 다시 시도해 주세요.`를 표시하고 재시도 버튼을 제공한다.

## 5. 데이터 모델

### Neon PostgreSQL 테이블
모든 점수 기록은 Neon PostgreSQL의 `game_scores` 테이블에 저장한다. 테이블 변경은 서버에서 실행할 SQL 스키마로 관리한다.

| 필드 | PostgreSQL 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| `id` | `UUID` | 기본 키, 기본값 `gen_random_uuid()` | 기록 ID |
| `nickname` | `VARCHAR(8)` | 필수, 길이 2~8자 | 저장 시 앞뒤 공백을 제거한 닉네임 |
| `score` | `INTEGER` | 필수, 0 이상 | 게임 최종 점수 |
| `level` | `INTEGER` | 필수, 1 이상 | 게임 종료 시 도달한 레벨 |
| `created_at` | `TIMESTAMPTZ` | 필수, 기본값 `NOW()` | 저장 시각 |

```sql
CREATE TABLE IF NOT EXISTS game_scores (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  nickname VARCHAR(8) NOT NULL CHECK (char_length(nickname) BETWEEN 2 AND 8),
  score INTEGER NOT NULL CHECK (score >= 0),
  level INTEGER NOT NULL CHECK (level >= 1),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_game_scores_ranking
  ON game_scores (score DESC, created_at ASC);
```

- 서버는 `@neondatabase/serverless`로 DB에 접근한다. DB 쿼리는 API 라우트에서만 실행한다.
- 개인 최고 점수는 서버 DB가 아니라 브라우저 `localStorage`의 `cup-shuffle-best-score` 키에 저장한다. 이 값은 랭킹 기록과 별개다.
- Supabase 데이터를 자동으로 이전하는 기능은 이번 구현 범위에 포함하지 않는다. 기존 DB 자격 증명과 데이터 내보내기 파일이 제공되지 않았으므로, 기존 데이터 이전은 별도 운영 작업이다.

### API 계약
#### `POST /api/scores`
- 요청 JSON: `{ "nickname": "민수", "score": 450, "level": 1 }`
- 서버는 JSON 형식, 닉네임의 앞뒤 공백 제거 후 길이 2~8자, `score`의 0 이상 정수, `level`의 1 이상 정수를 검사한다.
- 성공 시 HTTP 201과 `{ "success": true, "record": { "id": "UUID", "nickname": "민수", "score": 450, "level": 1, "createdAt": "ISO-8601 문자열" } }`를 반환한다.
- 유효하지 않은 입력은 HTTP 400과 `{ "success": false, "error": "INVALID_INPUT" }`를 반환한다. DB 오류는 상세 정보를 노출하지 않고 HTTP 503과 `{ "success": false, "error": "SAVE_FAILED" }`를 반환한다.
- 닉네임과 점수는 준비된 쿼리 매개변수로 전달한다. 클라이언트 검증만 신뢰하지 않는다.

#### `GET /api/scores/top5`
- 성공 시 HTTP 200과 `{ "records": [{ "id": "UUID", "nickname": "민수", "score": 450, "level": 1, "createdAt": "ISO-8601 문자열" }] }`를 반환한다. `records`는 0~5개다.
- SQL 정렬은 `score DESC, created_at ASC`이며 최대 5개만 조회한다.
- DB 오류는 HTTP 503과 `{ "success": false, "error": "LEADERBOARD_UNAVAILABLE" }`를 반환한다.

- 사용자가 운영체제의 움직임 줄이기 설정을 켠 경우 컵 이동 시간을 100ms로 줄이되, 정답 공개·상태 전환·입력 차단 규칙은 유지한다.

## 8. 품질 기준 (성능·보안·접근성)

### 보안과 오류 처리
- DB 연결은 서버 코드에서만 수행한다. 클라이언트에 `DATABASE_URL`이나 DB 오류 상세 정보를 보내지 않는다.
- API는 입력 형식과 범위를 서버에서 검사하고, 닉네임은 준비된 쿼리 매개변수로 처리한다.
- 로그인이나 사용자 인증은 없다. 따라서 요청 점수가 실제 게임 플레이에서 나온 점수인지 서버가 증명할 수 없다는 한계가 있다. API 입력 유효성 검사는 하되, 부정 점수 입력을 완전히 차단한다고 보장하지 않는다.
- 점수 저장 또는 랭킹 조회가 실패하면 게임 화면을 멈추지 않는다. 안내 문구와 재시도를 제공하고, 사용자가 입력한 닉네임과 현재 게임 결과를 유지한다.
- `localStorage` 접근이 불가능하거나 저장값이 손상된 경우 최고 점수를 0으로 사용하고 게임은 계속 진행한다.

### 화면과 조작 품질
- 320px 너비부터 PC 와이드 화면까지 가로 스크롤, 컵 겹침, 컵 잘림이 없어야 한다.
- 섞는 중에는 컵 선택을 막는다. 애니메이션 완료 이벤트가 누락되어도 이동 시간에 100ms를 더한 안전 타이머로 섞기를 계속한다.
- 컵은 `transform`으로 실제 슬롯 사이를 이동해야 한다. DOM이 고정된 채 위치 변화 없이 애니메이션만 재생되는 구현은 허용하지 않는다.
- 버튼과 컵 선택은 마우스와 터치에서 동작해야 한다. 컵은 키보드로도 선택할 수 있고, 버튼과 입력란에는 접근 가능한 이름을 지정한다.
- 모션 감소 설정이 켜져 있으면 컵 이동 전환을 100ms로 줄인다.

### 컵과 공의 시각적 정확성
- 모든 컵의 계산된 배경색은 `rgb(255, 255, 255)`, 불투명도는 `1`이어야 한다.
- 공은 `MIXING` 및 `CHOOSING` 상태에서 DOM에 없어야 한다. 이 상태에서 공의 위치를 컵 표면이나 투명 효과로 알아볼 수 없어야 한다.
- 컵 요소의 z-index는 공보다 높게 유지한다. 결과 공개 상태에서만 공을 표시한다.

## 9. 배포와 운영

### 배포
- GitHub 저장소에 push하면 Vercel이 Next.js 프로젝트를 빌드하고 배포한다.
- 빌드 명령은 `npm run build`다. Next.js 기본 빌드 결과 디렉터리인 `.next`를 사용하며 `dist`를 출력 디렉터리로 지정하지 않는다.
- Vercel의 서버 환경 변수에 Neon 연결 문자열 `DATABASE_URL`을 등록한다. 환경 변수 등록 후 새 배포를 수행한다.
- Neon에서 `data` 섹션의 `game_scores` 테이블 생성 SQL을 실행한 다음 점수 API를 사용한다.

### 운영 확인
- 배포 후 `GET /`은 DB 연결이 설정되지 않았더라도 HTTP 200으로 게임 화면을 렌더링해야 한다.
- DB가 준비된 환경에서는 `GET /api/scores/top5`가 HTTP 200 JSON을 반환해야 한다. DB 장애 시에는 명세된 HTTP 503 JSON을 반환하고 페이지 자체는 계속 열려야 한다.
- DB 접속 문자열이 포함된 `.env.local`은 GitHub에 올리지 않는다.

## 10. 테스트 계획

### 연기 테스트와 공개 경로
- `meta.smokeRoutes`는 `[/]`다. 서버를 띄우고 DB 설정 없이 `GET /`을 요청했을 때 HTTP 200과 게임 시작 화면이 렌더링되는지 확인한다.
- `/api/scores`와 `/api/scores/top5`는 DB 설정에 따라 성공 또는 명세된 오류를 반환하는 API다. 이 경로들은 DB 없이 200이어야 하는 공개 렌더링 경로가 아니므로 `smokeRoutes`에 포함하지 않는다.

### 기능 수용 테스트
- **카드 외관** — Given 컵이 3개 이상 렌더링되어 있을 때, When 각 카드의 계산된 CSS를 비교하면, Then 배경 `rgb(255, 255, 255)`, 불투명도 `1`, 테두리 색과 두께, 그림자가 모두 같아야 한다.
- **공 공개와 은폐** — Given 게임이 시작될 때, When 상태가 `PREVIEW`이면, Then 공이 정답 컵 아래에서 1,500ms 보이고 컵이 위로 50px 이동해야 한다. When 상태가 `MIXING` 또는 `CHOOSING`이면, Then 공 요소가 DOM에 없어야 한다.
- **실제 컵 이동** — Given 섞기가 시작될 때, When 한 쌍의 교환 애니메이션이 실행되면, Then 고유 ID를 가진 두 컵의 `translateX` 좌표가 바뀌고 화면에서 슬롯 사이 이동을 확인할 수 있어야 한다. 섞기가 끝나기 전 클릭은 선택으로 처리되지 않아야 한다.
- **레벨 설정** — Given 레벨 1~5 및 레벨 6의 게임 설정을 불러올 때, When 설정값을 확인하면, Then 표에 기재된 컵 수·교환 횟수·이동 시간·대기 시간이 일치해야 한다. 레벨 6 이상은 지정된 수식과 최솟값을 적용해야 한다.
- **정답 점수와 다음 레벨** — Given 레벨 1에서 정답을 선택했을 때, When 결과가 공개되면, Then 점수가 450 증가하고 1,200ms 뒤 레벨 2의 미리 보기와 섞기가 시작되어야 한다.
- **오답 종료** — Given 선택 대기 상태에서 오답 컵을 선택했을 때, When 결과가 공개되면, Then 오답 레벨 점수는 추가되지 않고 정답 컵과 선택 컵, 최종 점수, 닉네임 입력란이 표시되어야 한다.
- **최고 점수 저장** — Given 현재 점수가 기존 최고 점수보다 높을 때, When 게임 점수가 갱신되면, Then `cup-shuffle-best-score`에 새 점수가 저장되고 페이지를 다시 열어도 표시되어야 한다. 손상된 저장값은 0으로 처리해야 한다.
- **점수 저장 성공과 중복 방지** — Given 게임 종료 후 유효한 닉네임을 입력했을 때, When `POST /api/scores`가 HTTP 201을 반환하면, Then 기록 1개가 저장되고 버튼 문구가 `저장 완료 ✓`로 바뀌며 입력란과 버튼이 비활성화되어야 한다.
- **점수 저장 입력 오류** — Given 닉네임이 2자 미만 또는 8자 초과이거나 점수·레벨이 유효하지 않을 때, When API를 호출하면, Then HTTP 400과 `INVALID_INPUT`이 반환되고 DB에 기록이 추가되지 않아야 한다.
- **랭킹 정렬과 빈 상태** — Given DB에 6개 이상의 기록이 있을 때, When `GET /api/scores/top5`를 호출하면, Then HTTP 200으로 5개만 점수 내림차순·동점 시 생성 시각 오름차순으로 반환되어야 한다. 기록이 없으면 빈 배열을 반환하고 화면에 빈 상태 문구를 표시해야 한다.
- **API 장애 표시** — Given 저장 또는 조회 API가 실패할 때, When 화면이 오류 응답을 받으면, Then 정해진 안내 문구와 재시도 동작을 표시하고 게임 화면을 유지해야 한다.
- **모바일 레이아웃** — Given 화면 너비가 320px이고 레벨 5의 컵 5개가 표시될 때, When 컵이 서로 자리를 바꾸면, Then 모든 카드의 경계 상자가 서로 겹치지 않고 화면 좌우 안쪽에 있어야 한다.
- **키보드와 터치** — Given 컵 선택 대기 상태일 때, When 사용자가 키보드로 컵에 초점을 맞춰 선택하거나 터치로 누르면, Then 마우스 선택과 같은 정답·오답 처리가 되어야 한다.

| 카드 색상 | 모든 컵을 불투명 흰색 `#FFFFFF`으로 통일하고 같은 테두리·그림자 적용 | 요청한 색상 통일을 외관 전체의 동일성으로 구체화 | 색상 변경을 원하면 카드 공통 색상 토큰을 바꾼다. |
| 최고 점수 저장 위치 | 브라우저 `localStorage` | 로그인 없이 같은 브라우저에서 개인 최고 점수를 유지할 수 있다. | 여러 기기에서 공유하려면 계정 또는 서버 식별 방식이 필요하다. |
| 랭킹 기록 저장 시점 | 게임 종료 후 사용자가 닉네임을 입력하고 직접 저장 | 로그인 없는 플레이에서 닉네임을 확인하고 잘못된 저장을 줄인다. 저장하지 않은 게임은 랭킹에 포함하지 않는다. | 자동 저장을 원하면 종료 시 닉네임을 받을 별도 규칙을 정한다. |
| 닉네임 허용 범위 | 공백 제거 후 2~8자, 추가 문자 제한 없음 | 한글 닉네임을 허용하면서 DB 길이 제한과 일치시킨다. | 영문·숫자 등으로 제한하려면 서버와 화면 검증을 함께 바꾼다. |
| 레벨 6 이상 난이도 | 컵 5개를 유지하고 교환 횟수는 레벨마다 2회 증가, 이동·대기 시간은 정해진 최솟값까지 감소 | 레벨 5 이후에도 난이도가 계속 증가하도록 규칙을 고정한다. | 게임 밸런스 테스트 결과에 따라 `constants/levels.ts` 수식을 조정한다. |
| 점수의 서버 검증 한계 | 형식과 범위는 서버에서 검사하지만 게임 플레이 자체를 증명하지는 않음 | 로그인·외부 인증 서비스 없이 점수 위조를 완전히 막을 수 없다. | 강한 부정 방지가 필요하면 서버가 게임 진행을 검증하는 설계가 필요하다. |
| Supabase 기존 데이터 이전 | 자동 이전은 범위 밖이며 Neon 테이블은 새로 구성 | 기존 Supabase 접근 자격 증명과 내보낸 데이터가 제공되지 않아 실제 이전을 실행할 수 없다. | 이전이 필요하면 원본 데이터 파일과 접근 권한을 준비한 뒤 별도 이전 작업을 한다. |
| 데이터베이스 장애 처리 | 저장·조회 실패 시 사용자 메시지와 재시도 제공, 게임 플레이는 계속 가능 | DB 장애가 게임 진행을 막지 않도록 한다. | 운영 요구에 따라 재시도 횟수나 장애 안내를 조정한다. |

## 12. 아직 정해지지 않은 사항

미확정 사항 없음. 모든 기능 요구사항, 디자인, 데이터 모델 및 테스트 시나리오가 확정되어 즉시 개발 착수 가능합니다.
